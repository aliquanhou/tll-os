# TLL OS — Projection Contract

> **协议版本**: 2.0 | **契约状态**: beta | **所属模型**: 构建模型

---

## 一、Projection 是什么

Projection 定义 Application Graph 如何投影到不同输出形式。

Graph 是应用的主要事实来源。代码、OpenAPI、数据库 Schema、配置、文档、测试，都是 Graph 的 Projection。

Projection 是**双向**的：
- Graph → 输出（生成代码/配置/Schema）
- 输出 → Graph（同步/发现现有代码结构）

---

## 二、为什么需要 Projection

### 没有 Projection 时

```
Agent 修改 Graph（添加一个 API 节点）
  ↓
Agent 手动写对应的 Controller/Route/Test 代码
  ↓
容易遗漏、不一致、需要理解代码结构
```

### 有 Projection 时

```
Agent 修改 Graph（添加一个 API 节点）
  ↓
Projection 自动生成：
  - Controller 代码
  - Route 注册
  - OpenAPI 规范
  - 测试模板
  - 数据库 Migration（如果涉及 Model）
  ↓
Agent 审查生成的代码，运行测试，调整
```

---

## 三、Projection 类型

| Projection | 输出 | 说明 |
|------------|------|------|
| `code` | 源代码文件 | Module/Controller/Service/Model 代码 |
| `openapi` | OpenAPI 规范 | 从 API 节点生成 OpenAPI 3.0 文档 |
| `database` | DB Schema / Migration | 从 Model 节点生成 Drizzle Schema / SQL Migration |
| `config` | 配置文件 | 从 Config 节点生成 .env / yaml / json 配置 |
| `docs` | 文档 | 从 Graph 生成架构文档 / API 文档 / Module 文档 |
| `tests` | 测试代码 | 从 API/Service 节点生成测试模板 |
| `graphql` | GraphQL Schema | 从 Model/API 节点生成 GraphQL Schema |
| `typescript` | TypeScript 类型 | 从 Model/Config 节点生成 TypeScript 接口 |

## 四、Projection 定义

### Projection Manifest

```yaml
name: code-projection
version: "1.0.0"
description: "Project Graph to TypeScript code"
output_type: code
language: typescript

# 支持的节点类型
supports_nodes: [module, api, model, event, tool, agent, command]

# 投影规则
rules:
  - node_type: module
    output: "src/modules/{name}/index.ts"
    template: module_template
    dependencies: [api, model, event]

  - node_type: api
    output: "src/modules/{module}/controllers/{name}.ts"
    template: api_controller_template
    imports: [service, validator]

  - node_type: model
    output: "src/modules/{module}/models/{name}.ts"
    template: drizzle_model_template
    orm: drizzle

# 模板（可以是 EJS / Handlebars / 自定义）
templates:
  module_template: |
    // Auto-generated by TLL OS Projection
    export class {{name}}Module {
      // ...
    }

# 双向同步配置
sync:
  watch: ["src/modules/**/*.ts"]
  parser: typescript_ast
  update_graph_on_change: true
```

## 五、Projection 执行流程

### Graph → 输出（生成）

```
1. Agent 修改 Graph（添加/修改/删除节点）
2. Projection 引擎检测变更的节点
3. 根据 Projection Manifest 的规则，确定需要生成/更新哪些文件
4. 使用模板生成代码
5. Agent 审查生成的代码
6. 运行测试验证
7. 提交变更
```

### 输出 → Graph（同步/发现）

```
1. Agent 或开发者修改代码文件
2. Projection 引擎的 watcher 检测文件变更
3. 解析代码（AST / 正则 / 约定优于配置）
4. 更新 Graph 节点（添加/修改/删除）
5. Agent 可以通过 Graph 查询最新的应用结构
```

## 六、Projection 与 BuildTarget

Projection 是 BuildTarget 的基础。每个 BuildTarget 有自己的 Projection 配置：

```
BuildTarget: web
  Projections:
    - code (TypeScript + Fastify)
    - openapi
    - database (Drizzle + PostgreSQL)
    - config

BuildTarget: apk
  Projections:
    - code (TypeScript + React Native)
    - config (app.json)
    - database (SQLite)

BuildTarget: ai_agent
  Projections:
    - code (TypeScript + MCP Server)
    - openapi (Tool 定义)
```

## 七、Projection 冲突解决

当 Graph 和代码不一致时（例如开发者手动修改了代码，Graph 还没更新）：

| 策略 | 说明 |
|------|------|
| `graph_wins` | Graph 是事实来源，重新投影覆盖代码 |
| `code_wins` | 代码是事实来源，同步更新 Graph |
| `merge` | 尝试合并，冲突时标记需要人工审查 |
| `ask` | 暂停，询问 Agent/开发者如何处理 |

默认策略是 `merge`，冲突时 `ask`。

## 八、第一阶段实现范围

Protocol 2.0 定义 Projection Contract。Runtime 0.x 实现：
- Projection Manifest 格式
- 基本的 code projection（Module/API/Model 代码生成）
- openapi projection（从 API 节点生成 OpenAPI）
- Graph → 代码的单向生成
- 简单的模板系统

双向同步、database projection、复杂冲突解决、多语言 projection 留到后续版本。
